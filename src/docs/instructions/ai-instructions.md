## 🛠️ Технологический стек
- **Сборка:** Vite (dev / build / preview).
- **Frontend:** React + TypeScript (строгая типизация, без использования `any`).
- **Стилизация:** SCSS (используй CSS/SCSS модули `*.module.scss` для изоляции стилей компонентов, используются светлая/тёмная темы).
- **Хранение данных (Data Layer):** 
  - **IndexedDB:** Для важных доменных данных приложения (управляется через слои репозиториев).
  - **localStorage:** Для настроек приложения, конфигураций UI (включая текущую тему оформления: light/dark) и временных кэшей внешнего слоя.

## 📐 Архитектурные слои (Гексагональная архитектура + MVVM)

Приложение разделено вертикально на независимые слои по принципу гексагональной архитектуры. Бизнес-логика должна быть полностью отделена от деталей реализации инфраструктуры и UI.

### 🧠 Слой 1: Центральное Ядро (Domain / Core) — ТОЛЬКО ЧИСТЫЙ TS
Этот слой ничего не знает про React, DOM, HTML, `fetch` или конкретные базы данных.
- **Доменные модели (Domain Models):** Чистые типы данных и интерфейсы сущностей приложения (например, `User`, `Account`, `Transaction` для планов счетов).
- **Доменные сервисы (Domain Services):** Классы или функции, содержащие **всю главную бизнес-логику и математику приложения**. 
  - *Пример:* Расчет двойной записи, проводка транзакций, валидация баланса, контроль овердрафта активных счетов и изменение планов счетов происходят **только здесь**.
  - Доменные сервисы общаются с базами данных исключительно через абстрактные Порты (Интерфейсы репозиториев).

### 🔌 Слой 2: Порты (Ports / Interfaces)
- Интерфейсы репозиториев (например, `interface AccountingRepository`). Они описывают контракт: какие методы для сохранения и получения данных доменное ядро требует от инфраструктуры.

### ⚙️ Слой 3: Адаптеры (Adapters / Инфраструктура)
- Конкретная реализация Портов. Здесь пишется грязный код работы с **IndexedDB** (классы-репозитории). Вся работа с базами данных должна быть инкапсулирована здесь. В будущем эти адаптеры могут быть заменены на HTTP-клиенты для бэкенда без изменения логики ядра.

### 🖥️ Слой 4: Внешний презентационный слой (UI / MVVM)
Слой отображения и ввода параметров пользователем. Реализуется строго через паттерн **MVVM**:
- **View (Компоненты React):** Чистая разметка и стили. Компоненты «глупые», они не содержат логики `useState`, `useEffect` для бизнес-задач или прямых обращений к репозиториям/сервисам.
- **ViewModel (Кастомные хуки):** Находятся на стыке UI и Ядра. Хук принимает сырые параметры ввода из View (например, данные формы транзакции) и передает их в соответствующий **Доменный сервис** на обработку. Также хук управляет чисто интерфейсным состоянием (стейт загрузки `loading`, ошибки `error`, видимость модалок).

## 📂 Структура проекта и Правила колоккации (Colocation)

Код должен быть организован по принципу самодостаточных модулей. Файлы не должны «болтаться» в корневых директориях без структуры.

### Основные директории:
```text
src/
├── core/                               # Слой 1: Чистое Ядро (Только TS, без привязки к UI)
│   ├── entities/                       # Описание сущностей (Account, Transaction, User)
│   └── services/                       # Бизнес-логика (AccountingService - Двойная запись, контроль овердрафта)
│
├── ports/                              # Слой 2: Порты (Контракты для внешнего мира)
│   └── AccountingRepository.ts         # TypeScript-интерфейс для баз данных
│
├── adapters/                           # Слой 3: Адаптеры (Детали реализации инфраструктуры)
│   ├── IndexedDbAccountingAdapter.ts   # Код работы с IndexedDB
│   └── LocalStorageSettingsAdapter.ts  # Работа с localStorage для настроек
│
├── application/                        # ВНЕШНИЙ УРОВЕНЬ — UI, состояние, роутинг
│   ├── common/                         # Глобальный слой (переиспользуемый код)
│   │   ├── components/                 # Общие UI-компоненты (Кнопки, Инпуты, Модалки)
│   │   │   ├── Button/
│   │   │   │   ├── Button.tsx
│   │   │   │   └── Button.module.scss
│   │   │   └── Input/
│   │   ├── hooks/                      # Общие технические хуки (useTheme, useLocalStorage)
│   │   ├── helpers/                    # Чистые утилиты (форматирование дат, валют)
│   │   ├── types/                      # Глобальные технические типы приложения
│   │   ├── utils/                      # ThemeContext и инфраструктурные утилиты
│   │   ├── styles/                     # main.scss, глобальные темы (_themes)
│   │   └── dependencies.ts             # Точка сборки (Инициализация репозиториев и синглтонов)
│   │
│   ├── router/                         # Роутинг приложения
│   │   ├── routes.ts                   # Список путей и маппинг страниц
│   │   └── AppRouter.tsx               # Компонент провайдера роутера
│   │
│   └── pages/                          # Интерфейс приложения (Паттерн MVVM)
│       └── Home/                       # Изолированный модуль главной страницы (Дашборд)

│           ├── Home.module.scss        # Стили, уникальные для этой страницы
│           ├── Home.types.ts           # Типы, нужные только внутри страницы Home
│           └── components/             # Подкомпоненты, используемые ТОЛЬКО на этой странице
│               ├── AccountCard/        # Карточка аккаунта
│               │   ├── AccountCard.tsx
│               │   ├── AccountCard.module.scss
│               │   └── AccountCard.types.ts
│               └── UserInfo/           # Блок информации о пользователе
```

### 🏗️ Структура папки конкретной страницы (внутри `src/pages/`)
Каждая страница должна содержать в себе все необходимые для её работы ресурсы (View, ViewModel, внутренние компоненты и стили):

```text
src/pages/[PageName]/
├── [PageName].tsx              # Главный View компонент страницы
├── use[PageName].viewModel.ts  # ViewModel (хук управления логикой страницы)
├── [PageName].module.scss      # Стили, специфичные для страницы
├── [PageName].types.ts         # Типы/интерфейсы, используемые только на этой странице
└── components/                 # Подкомпоненты, используемые ТОЛЬКО на этой странице
    └── [SubComponent]/
        ├── [SubComponent].tsx
        ├── [SubComponent].module.scss
        ├── [SubComponent].types.ts # Типы, нужные только этому подкомпоненту
        └── [SubComponent].model.ts # Специфическая локальная модель/логика компонента
```

## 🚫 Ключевые ограничения для Агента

1. **Правило размещения типов:** Локализуй типы там, где они используются.
   - Нужны только в одном компоненте? Кладешь `*.types.ts` в папку с этим компонентом.
   - Нужны на уровне страницы? Кладешь в корень папки этой страницы.
   - Общие для нескольких страниц? Кладешь в `src/common/types/`.
2. **Изоляция стилей:** Стили конкретного компонента (`*.module.scss`) всегда лежат в одной папке с файлом этого компонента.
3. **Чистота View:** Внутри компонентов во `views` и `pages` запрещено напрямую вызывать IndexedDB, localStorage или описывать тяжелые цепочки состояний. Сначала создай или обнови метод во ViewModel / Репозитории.
4. **Стандарт темизации приложения (Светлая/Темная тема):**
   - **Архитектура:** Переключение темы реализовано через `ThemeProvider` в `src/application/common/utils/context/ThemeContext.tsx`. Для получения темы и функции переключения в компонентах ВСЕГДА используй хук `useTheme` из `src/application/common/utils/context/ThemeContext.tsx`.
   - **Хранение:** Состояние темы кэшируется в `localStorage` под ключом `'app-theme'`. По умолчанию используется тёмная тема (`'dark'`).
   - **Связь с UI (HTML-атрибут):** Провайдер автоматически управляет атрибутом `data-theme` на теге `html` (`<html data-theme="light">` или `<html data-theme="dark">`).
   - **Правила для SCSS:** При стилизации компонентов категорически запрещено хардкодить цвета. Используй нативные CSS-переменные, которые объявлены в глобальных стилях `src/application/common/styles/` через селекторы атрибутов:
     ```scss
     [data-theme="dark"] { --bg-primary: #121212; }
     [data-theme="light"] { --bg-primary: #ffffff; }
     ```
   - Внутри локальных `*.module.scss` файлов страниц и компонентов применяй эти переменные напрямую: `background-color: var(--bg-primary);`.
   - Если надо завести переменную в глобальных стилях, используй селекторы атрибутов: `[data-theme="dark"] { --bg-secondary: #222222; }`.
